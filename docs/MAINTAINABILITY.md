# 可维护性整改约束与验收标准

用户要求：可维护性达到9.0以上前暂停原功能开发；不损坏插件、不丢核心功能。本轮基线30cf4dc/1.12.0，目标1.13.0，只做结构、诊断、工程与验收能力整改。

## 评分规则

每项0–10分，七项等权平均必须严格大于9.0。每项须给可核对证据，不用行数下降代替职责边界。独立审查逐项复评；有未解决Critical/Important、核心功能回归、真实验收失败、安装/回退不明确时，整体不得达标。评分是工程判断，不是第三方认证。功能能力和模型语义质量另评，不因本轮维护性分数提高而宣称全部目标完成。

| 项目 | 9分以上的证据 |
|---|---|
| 模块边界 | 入口只负责装配；按业务责任拆分服务、工具、路由和面板；显式模块依赖，无eval/全局服务容器和循环依赖；有自动边界检查 |
| 契约一致性 | 记忆操作字段/required来自同一冻结定义；工具schema、核心校验、后台能力和建议策略引用；不同入口权限仍独立收紧 |
| 诊断 | 建议拒绝有稳定原因码、失败阶段及安全修复建议；预期错误可区分，未知错误不泄漏原文/凭据；真实拒绝样例可复现 |
| 构建复现 | 单一提交锁文件、固定dev版本、CI冷安装；面板源码可确定构建，过期产物检查；运行安装不要求编译或新增重型服务 |
| 验证 | 既有23套不减，增加契约/边界/诊断/构建检查；打包干净安装；真实前台/后台及新会话召回复验；缺开发依赖不能假绿 |
| 交付恢复 | 明确安装目标安全校验、先暂存再替换、失败恢复旧插件、有测试；备份安装/正常重启/文件与API核对/CI；不改正式记忆 |
| 可接手性 | 当前架构、修改路径、错误码、测试命令和发布回退runbook集中；真实验收驱动参数化入库，脱敏证据；当前交接与历史明确 |

## 功能保持清单

- 唯一self层级、模型自定核心/归属/关系；原文/来源/认知类型/版本/历史/幂等收据/preview一致性。
- 当前核心+旧库检索/迁移/撤回；不新增默认embedding下载。
- 接收队列、完整材料补读、预算/冷却、单飞/取消、后台建议不自动执行。
- 私聊与群聊范围/自定义群目录/群关闭、QQ通道/发件箱、人格、情绪、心跳和主动行为。
- 面板所有页、自动/手动缩放、群切换、记忆详情；主/备用星图字节保持不变。
- 公开包入口/宿主client注册保持兼容；无正式测试数据、无认证/TLS/代理改动。

## 实施顺序

先保存兼容基线与失败测试，再统一契约/诊断，随后服务和面板模块化、可复现构建、部署恢复，最后完整/真实/安装验收与独立复评。不做全盘重写；每次搬移用已有行为测试，保持已授权本地Git/远程维护和正常重启流程，不发布npm/标签/Release。

## 实现顺序与完成标准

| 阶段 | 实现 | 完成标准 |
|---|---|---|
| 1 质量基线与接收诊断 | 条件、否定、引用、说话人、假设和局部修正的可重复真实模型验收；显示本次插件启动后的接收/入队/失败情况 | 检查输入、实际文件、来源、队列及新会话回答；失败保留，不因一句“记住了”判成功；正式库不写测试偏好 |
| 2 统一检索 | 核心和旧库统一候选、关键词/可选语义/关系检索、当前与历史区分 | 换措辞能找到；群隔离不退化；可追溯命中来源；记录召回与耗时基线 |
| 3 受控自主整理 | 候选冲突、核心复用/合并、旧库整理、长材料分段和安全合批 | 模型决定语义，预算不绕过；原文、撤回和来源保留；重复、不完整材料与积压可解释 |
| 4 经历与人格/情绪/行为衔接 | 稳定人格底色和动态自我摘要分开；状态以事件为依据，后台使用有界人格上下文 | 明确经历能影响后续表现；心情与原因一致；初始黏人设定不覆盖真实关系；推测不冒充经历 |
| 5 持续验收（贯穿后续阶段） | 7–14天日常/群聊观察，断网、重启、规模、备份与迁移 | 记录误记、漏记、重复核心、积压、模型用量和资源变化；达到约定标准后称稳定日用测试版 |

原阶段之后新增：6可执行技能闭环、7独立身体软件、8语音/视觉/复杂技能联合验收；门槛、职责和停止条件见新增完整路线。旧3–5周估算不覆盖新增两条研发线，隔离原型后重新估算。

每轮执行：确定范围与失败用例 → 自检 → 隔离真实对话 → 检查实际文件/来源/回答 → 针对证据修复 → 完整回归 → 备份安装并正常重启 → 版本评估报告 → Git提交推送与远端CI。阶段完成依赖验收，不依赖日期。主要开发估计8–15个工作日，观察可部分并行，总体3–5周为估算，尚无证据保证因参考开源就缩短到具体天数。

## 开源研究与复用决定

2026-11-01查阅官方仓库/文档，未复制代码或数据、未安装新运行依赖。

| 项目/许可证 | 可借鉴内容 | 本项目决定 |
|---|---|---|
| [Mem0](https://github.com/mem0ai/mem0)，Apache-2.0 | 记忆提炼、更新与评估路径 | 比较其候选及更新设计，保留当前可追溯/可撤回存储；不以其公开指标当作本项目性能 |
| [Graphiti](https://github.com/getzep/graphiti)，Apache-2.0 | 当前/历史关系与语义+关键词+图遍历 | 阶段2/3参考；官方完整框架需要Python与图数据库等，本轮不增加这些服务 |
| [Letta](https://github.com/letta-ai/letta)及[当前源码letta-code](https://github.com/letta-ai/letta-code) | 持久身份及有界记忆上下文；原仓库当前指向letta-code，旧V1在archive分支 | 阶段4参考身份与记忆区分，不替换DSH宿主；具体代码复用前重新核查目标路径许可证 |
| [LangMem](https://github.com/langchain-ai/langmem)，MIT；[概念文档](https://langchain-ai.github.io/langmem/concepts/conceptual_guide/) | 语义/情景/程序记忆、前台工具和后台整理；过度提炼与漏提炼权衡 | 阶段1先分别评估提炼、更新、召回；阶段3参考后台合并调度，不引入LangGraph运行时 |

节省资源的方式：复用设计与测试维度，沿用已有Node/DSH模型接口和文件存储；CI只跑离线契约测试，真实模型验收显式运行；不为单用户插件引入第二套agent宿主。未来若直接复制代码/数据，需固定版本、保留许可证并在CREDITS登记。

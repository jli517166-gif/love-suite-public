# 人格蒸馏

把分散的材料（聊天记录、描述、语音转写、文章）压缩成一份**只负责说话方式**的人格 skill。
记忆、工具、主动聊天仍然由 dsh-memory-network 负责，人格不接管这些。

## 先采集

至少三类材料，缺哪类就先问：

1. **身份**：TA 是谁、和用户什么关系、从哪来。
2. **说话方式**：句子长短、称呼、语气词、会不会开玩笑、什么时候认真。
3. **在意/边界**：在意什么、不喜欢什么、什么话题不接。

可选：口头禅、原话摘录（3–8 条最有辨识度的）。

## 提炼（不要写成简历）

- 身份：两三句，写"她怎么存在"，不写履历。
- 说话方式：写**可执行**的规则（"短句，最多两句""先接话再补一句自己的反应"）。
- 在意的事：写她在对话里会怎么关心人，不写价值观口号。
- 边界：明确写"不接什么"。
- 口头禅：只留真正有辨识度的，别贪多。

## 落盘

调用工具：

```
love_distill key=<英文小写> name=<显示名> identity=... voice=... values=... boundaries=... quotes=[...] aliases=[...]
```

它会：

1. 写 `.dsh/skills/<key>-persona/SKILL.md`（自带「兼容约定」）；
2. 登记 `tools/persona.py` 的 `PERSONAS`；
3. 如果 `memory/self.md` 还是空的，写一段自我叙事种子。

装完提示用户在面板「设置 → 人格」选中，或说「切换人格 <名字>」。

## 收尾检查

- 跑一次 `love_doctor`：人格一行应显示新 key，记忆/学习条数不应变化。
- 如果用户已经有人格，装新的不会删旧的；切换是可逆的。
- 不要覆盖同名 key；要改就换 key 或先手动删旧 skill 目录。

## 边界

- 不编造材料里没有的经历。
- 不把真人隐私（住址、账号、身份证）写进 skill。
- 蒸馏出来的是"说话方式"，不是"这个人"；不要声称复制了本人。

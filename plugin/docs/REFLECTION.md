# 会话增量整理（1.9.0）

本版自动收集已完成轮次中的真实文字材料，保存为待整理队列。后台使用原会话所选模型，自行判断核心名称、归属、关联、重要性或跳过。插件检查来源角色、引用、版本和数据结构，再保存核心变化；也保留后续正常对话中的手动整理工具。

**后台提炼会额外消耗模型预算，默认开启，可在设置中暂停。** 收集材料本身仍不调用模型。后台独立运行，不需要再发消息，不向 QQ 或聊天注入整理提示，也不自动回填加载前历史。

## 收集与范围

- 接入当前宿主的 `ctx.on('session/event', (session, event) => …)`；在 `turn/end` 且 `reason.kind=completed` 时收集。
- 从 `firstLiveSeq` 或已保存游标读取本会话自有事件。只接受 `user`、已回答的 `user-question-reply`、`plugin:dsh-onebot` 用户来源，排除框架上下文、失败/中断轮次、子代理和旧主动消息提示。
- 保存用户文字、非中断助手正文及有对应调用的成功工具结果；不保存助手推理块，也不再次收集本插件 `love_*` 工具回传的记忆与状态。来源引用为实际 `sessionId#messageId`，并保留角色、序号、工具名称。
- 工作区必须符合插件原有配置；群聊按会话群号和群工作区单独保存，不混入私聊队列。
- 设置中的“会话记忆整理”（`reflectionEnabled`，默认开启）控制材料收集、模型提醒及后台执行。关闭时仅推进轮次游标，不保存该轮正文，重新开启也不追补关闭期间的材料；已入队材料仍可手动查看、处理。群记忆关闭时同样只推进群游标，并停止对应群后台任务。
- 新批次仅保存实际请求头中的 `provider/model` 路由，不复制凭据或其他连接配置。旧批次没有路由时，等待原会话打开后取得其模型，不擅自换成另一个模型。

每轮自动提炼材料仍最多64条、合计32000字符，单条最多4000字符；截断、附件或非文字块会标为 `needs_review`。后台实际请求另有24000 UTF-8字节上限，包含指令、来源和核心上下文，超限也转待补读。1.8.0新增原始文字快照：新批次最多保存256条、合计256000字符的可支持文字，排除内部上下文、推理和本插件工具结果。有附件、缺失标识或超限时快照仍不完整；旧批次没有快照时不能从节选恢复全文。附件解析和原宿主历史补抓仍未实现。

## 后台执行与预算

通过宿主 `llm.prepareCall(config, signal, configure)` 固定模型和输出上限，再调用一次 prepared stream；使用该模型最低可选推理强度，不继承主聊天的高推理/大输出设置。不向后台提供执行或发消息工具，只接收结构化 JSON。

| 配置 | 默认与范围 | 含义 |
|---|---|---|
| `reflectionBackgroundEnabled` | true | 仅控制后台调用；关闭后仍可收集并在正常对话中整理 |
| `reflectionCooldownMinutes` | 10，1–1440 | 同一配置工作区及其群共用调用间隔 |
| `reflectionMaxCallsPerDay` | 6，1–24 | 同一配置工作区及其群共用每天调用上限，按调用开始的 UTC 日 |
| `reflectionMaxOutputTokens` | 4096，512–8192 | 单次输出和推理 token 上限；不是费用金额保证 |

整个插件一次只运行一个后台批次；5 秒轮询待处理队列，不在每次心跳调用模型。后台超时为 90 秒；文本输出另限 48000 UTF-8 字节。输入字节限制不等于精确输入 token 数，实际用量只在宿主提供 usage 时保存，缺失用量不当作零。

预算在调用前原子预留，取消和异常也保留这次计数，避免重启或反复失败绕过上限。冷却、计数和最近 20 次运行结果保存在主工作区 `memory/reflection-worker.json`；同一配置工作区的私聊与群共用此文件，多配置工作区各有预算。后台开启期间，已有的完整待处理批次也可能自动被处理。

设置中的“后台整理”可调整预算、暂停/继续，并查看最近结果和宿主报告用量。通过面板关闭会立即发出取消；卸载、导入、重置或迁移群目录时同样先取消并等运行收尾。迟到模型结果不再提交。取消不能撤回已经由提供方处理的请求或计费。只用外部文件直接修改配置时，最迟在提交前重新核对，不保证提供方立即停流。

后台支持 `create_core/record_memory/link/attach_source/supersede_memory/update_core`，由模型决定形成核心、归属、关联、重复来源和明确取代。上下文改为全部有效核心的完整摘要、最多 8 条相关/最近记忆的完整正文；目标未完整提供时拒绝操作，整体超过输入预算则转待补读。不传操作日志、私聊概况、模板或其他群记忆。后台是同一模型路由的一次独立提炼，不继承主会话全部人格提示及历史；长期语义质量与人格连贯性仍需真实对话观察。

## 模型工具

`love_reflection` 不接受任意工作区或群号，始终由当前会话决定范围。

| action | 行为 |
|---|---|
| `status` | 状态数量、当前可处理/需回收租约数量及队列版本 |
| `list` | 按status（active/all/具体状态）分页；offset每页20条，包含原因、次数与结果 |
| `read` | 按jobId读节选、全文可用性、重试记录及结果；不一次回传整个快照或读进度凭据 |
| `next` | 不带jobId领取完整短批次；带jobId领取指定needs_review的完整文字快照，返回五分钟leaseToken |
| `material` | 带jobId/leaseToken/offset，从0顺序读每页最多3000字符；拼接text为材料JSON，最后页给readToken |
| `retry` | jobId/reason/队列expectedRevision，重开pending/failed，每批最多手动3次，保留后台预算与冷却；缺失材料和进行中拒绝 |
| `complete` | jobId,leaseToken,核心expectedRevision,operations,reason；补读批次还须最后页readToken；一次0–20项核心操作 |
| `fail` | `jobId,leaseToken,reason`；按退避时间等待后续重试 |
| `skip` | `jobId,reason`；仍在有效领取期时还需 `leaseToken`，保留理由 |

先 `love_core_memory read` 查看当前核心和版本，再用 `complete` 提交。支持 `create_core/record_memory/attach_source/supersede_memory/update_core/update_memory/link/archive`，旧记忆迁移仍走原工具。操作字段见 [核心记忆说明](CORE-MEMORY.md)。空 `operations:[]` 表示没有值得新增的内容，只保存跳过理由，不创建核心文件。

全文快照按内容摘要绑定，读进度绑定当前租约，只允许顺序页。换租约或重试后旧readToken失效；缺页、缺失附件或不完整快照不能非空提交。回执检查返回范围，不证明模型理解正确。长文页数多仍可能超出五分钟租约或模型上下文，需要重新领取/缩小材料，不能声称支持无限长文。面板只读翻页不领取、不产生模型可提交的readToken。

新增记忆、绑定来源、取代记忆，或修改已有记忆的正文、来源、认知类型，必须明确填写本批 `materials` 中的来源引用及 `epistemic`：

- `conversation` 只能引用用户材料，标为 `reported` 或 `inferred`。
- `tool_result` 只能引用成功工具材料。
- `reflection` 必须标为 `inferred`；模型自己的理解不能转述成用户陈述或工具经历。

这些检查验证引用存在及角色匹配，**不证明内容在现实中为真，也不证明提炼语义必然符合原文**。模型仍须核实证据和冲突；通过宿主 `love_core_memory commit` 也会检查实际 Session 来源，底层无 Session 的独立模块集成仍须自行提供来源保障。

## 持久化与恢复

私聊文件为 `memory/reflection-queue.json`，群文件为当前群工作区的 `memory/groups/<群号>/reflection-queue.json`。每次修改通过临时文件重命名保存；坏文件报错，不自动清空。队列和核心回执均纳入导入导出。

- 一个范围最多保留 100 个未完成/失败/需补读批次、50 个完成或跳过批次、1000 个会话游标。完成数量是保留窗口统计，不是终身累计。
- 满载时不越过未保存材料的游标；有空位后该会话再次触发轮次事件时补入。尚无独立扫描历史会话的后台恢复器。
- 每次领取有效期 5 分钟；最多领取 3 次。显式失败按 1、2 分钟退避；第三次失败或超时后停止自动重试。过期处理在后续 `next` 时进行。
- 手动retry可在明确理由下重开最多3轮，保存每次理由；不重置后台调用预算和冷却。有效租约不可由面板抢占；补读租约过期回到needs_review，不把节选投进自动提炼。
- 核心变化和 `reflection:<jobId>` 回执保存在同一个核心文件。若核心保存后、队列确认前退出，下一次领取会按回执恢复确认；同批重试不重复写入，也不覆盖后来产生的记忆。
- 回执目前不自动清理，避免清除幂等依据；后续需制定与游标/备份一致的保留规则。当前串行同步文件操作针对单个宿主进程，不支持多个 DSH 进程并发写同一范围。
- 后台会在预算耗尽或冷却时仍回收过期租约、确认已保存回执；不因此再次调用模型。取消会归还领取次数，实际模型预算不退回。异常退出的运行保留为中断记录，并等待租约/回执恢复。

概览“查看整理批次”进入设置→后台整理。面板提供状态筛选、列表分页、批次详情、原文翻页、处理理由、重试和跳过；群面板共享记忆区提供当前群相同功能，切换范围清除上一范围材料。列表只含150批保留窗口，不代表全部历史。

1.9.0的状态API新增reflectionCapture，后台整理设置显示接收诊断：当前配置工作区（含群）在本次插件启动后收到的轮次结束次数、入队批次、关闭收集、收集失败、满载次数和最近入队时间。计数只在内存中保留，重启清零；不保存正文、会话ID、额外路径或错误原文。outsideScopeTurns只给出其他范围的结束事件计数，不表示其内容被收集。收到结束事件不等于入队，未完成轮次、没有合适用户材料、已处理游标或关闭收集均可能不新增；零计数只表示尚未观察到事件，不证明链路成功或故障。正式工作区需实际正常对话后再验收。

本地API `/love-companion/api/reflection` GET支持status/offset/groupId；jobId读取脱敏详情（不回传租约、读进度或整个快照），jobId+material=1分页读原文。POST仅retry/skip，必填当前队列expectedRevision及reason；拒绝跨站写。后台处理期间版本变化需刷新，面板不持有后台租约，也不暂停后台抢占。

## 群聊召回

`love_recall` 从会话 ID 及当前群工作区判定范围，即使群会话缓存尚未建立也不会退回私聊。只返回当前群核心、笔记及发言人关系，不读私聊偏好、日记、meow、自我、活动或心情原因。群聊也不注入私聊心情原因。

群中不能调用本插件的私聊记忆/人格管理工具，`love_group` 不能跨群。私聊模块仍保留。群上下文读取实际配置的群目录。本次修正不追溯清除旧群记录，也不能约束宿主或其他插件提供的任意文件、网络等工具。

## 后续

本轮已在隔离目录进行了真实模型对话和真实后台提炼，证据见仓库 `docs/reports/evidence/1.6.0-live-dialogue.json`。真实验收脚本为 `patches/live-dialogue.mjs`，仅显式传 `--run-live` 才运行，会实际调用所选 DeepSeek 账号模型，默认自检和 CI 不运行它。CLI 夹具为每次真实会话前等待同一个 worker 处理上一轮材料；默认五秒定时器由另一组宿主集成自检覆盖。

1.7.0已增加旧档案/学习的选择性迁移与当前读取保护，1.8.0新增逐条批次管理和新批次完整文字补读。后续推进条件偏好/引用/说话人质量评估、受控旧库整理和全库语义检索。当前不根据模型输出自动认定现实真假，也未实现完整人格推演、附件解析或任意宿主历史恢复。

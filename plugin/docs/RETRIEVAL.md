# 当前记忆统一检索（1.10.0）

`love_recall`带query时，从当前会话的范围统一读取核心和旧库候选，再一次选出最多12条；不带query继续提供近期概况。群关闭时不检索；群会话只读当前群的核心/共享笔记及当前发言人信息，支持已配置的群目录，不读私聊或别群。

## 候选与当前状态

- 有效核心记忆的正文、所属核心名称及已有关键词；来源为当前正文实际绑定的引用。
- 旧meow支持表、日记（含旧档）、小生活、自我、记忆网事件，以及未迁移的profile/learning；沿用旧图谱的只读收集，不受星图900节点或最近90天的展示窗口限制。
- 排除归档核心/记忆、归档旧表行和仍绑定的迁移旧快照。归档/取代不会复活对应旧来源；外部改变旧文件形成的新快照仍可见，不由检索层静默裁定冲突。
- 原文只按空白/大小写归一后的精确内容去重，合并引用和旧节点别名；不做语义合并、改写或自动迁移。
- 旧记录标legacy-unverified；能读到不等于核实真实。查询层不自行提升认知类型。

旧meow表没有显式id时，图谱/检索用表名与正文的SHA256生成稳定内容ID，仅读取，不写数据库。正常id表仍使用原id。表或文件不可读时沿用旧收集器的降级，不能据此保证所有历史数据都完整存在。

## 排名与资源边界

1. BM25及现有本地同义词对全部收集到的当前候选检索；核心名称也参与。例如“中意”可以匹配“喜欢”，核心名称可帮助找正文没出现的主题词。没有可检索词的纯标点返回空，不把最近条目伪称命中。
2. 若安装并启用可选dsh-love-semantic且提供rankBySemantic，独立从最多256条候选尝试有界语义检索：关键词前96条加候选列表尾部补充，每条投影最多4000字符；最多接收20条、有限分数>=0.5的结果。阈值只是保守工程门槛，未形成真实模型质量标定。
3. 关键词与语义以倒数排名相加（1/(60+排名)）融合。语义可发现池中没有词面命中的条目；不能召回未送入池的记录，不声称全库语义召回。
4. 从前4个直接命中记录的有效图谱边补充最多3条一跳关联，占用同一个12条总额度；没有直接命中不扩散，不递归，不穿过归档端点。直接关联单独标注via与关系，不冒充正文命中或事实证明。

语义接口只收到当前范围的id/text投影，返回项必须来自这次池，实际正文/来源仍从本地原候选读取，外来ID、伪正文、重复结果及无效/低分丢弃。等待上限1200ms，缺包/失败/超时退回关键词。整个模块最多一个未结束的语义请求，忙时直接降级，避免超时请求持续堆积；超时仅停止等待，无法强制停止第三方模型内部计算/下载或同步阻塞。包安装后重启宿主再检测。

本轮不自动安装包、不下载embedding模型、不调用云模型作检索。正式本机未安装可选语义包，实际运行是关键词/同义词/直接关联；合成接口边界测试不等于真实embedding质量。

## 返回与追溯

每项带稳定ID、正文当前引用、原始/推测/旧未核实类型、命中方式。正文超过500字符时，围绕可匹配查询词给出节选，明确标“正文截断”，不能用节选覆盖完整记忆。核心正文/历史可用love_core_memory read按ID查看；超长旧正文需要原始记录或现有详情，不声称旧迁移预览能完整补读。

工具文本报告候选量、结果量及语义状态/池大小；不回传私聊到群。searchMemories模块另返回只读metrics：scope、coreRevision、totalCandidates、duplicateCount、lexicalHits、semanticStatus、semanticCandidates、semanticTextTruncated、relationHits、elapsedMs。耗时包含本次候选收集和排名，不含模型回答；随机器/规模/文件/可选模型而变化。

未知问题只报告本次未命中，不断言事情从未发生。没有跨库语义冲突自动裁决、持久化向量索引或无限规模保证。后台整理的有界上下文选择本轮仍用原路径，后续与统一检索对接时需单独验证预算及完整目标约束。

## 验收

verify-memory-search覆盖当前过滤、旧迁移、核心名称/同义词、长文、无命中、语义范围/正文/超时降级、一跳上限、1211候选规模以及真实宿主工具的群自定义目录/关闭与隔离。live-retrieval-dialogue.mjs仅显式--run-live执行，使用真实工具写入核心/旧学习，再换措辞召回、修正、新会话及未知问题；默认CI不调用付费模型。
